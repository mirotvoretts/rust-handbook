# M01 — Значения, привязки и поток управления

> Часть I «Основы языка». Это первый содержательный модуль. Предполагается, что тулчейн уже
> установлен (M00): вы умеете `cargo new`, `cargo test`, читать ошибки компилятора.
> Дальше: [M02 Скалярные и составные типы](../02-scalar-compound/README.md).

## Цель модуля

Освоить самый нижний слой синтаксиса Rust — то, из чего состоит тело любой функции: **привязки
значений** (`let`/`mut`/`const`), **выражения против инструкций**, и **поток управления**
(`if`, `loop`, `while`, `for`). Ключевая идея, отличающая Rust от C, C++, Java и Python:
**почти всё в Rust — выражение**, у которого есть значение и тип. `if`, `match`, `loop` и блок
`{ ... }` можно присвоить переменной. Это не косметика — это меняет то, как пишется код.

После модуля вы умеете:

- [ ] объяснить, почему привязки **неизменяемы по умолчанию** и когда нужен `mut`;
- [ ] различать `let`, `const` и `static`, и знать, что вычисляется на компиляции;
- [ ] отличать **выражение** (имеет значение) от **инструкции** (не имеет) и видеть, где
      «висячая точка с запятой» меняет тип блока;
- [ ] использовать `if`/`match`/`loop`/блок **как выражение** — присваивать и возвращать их;
- [ ] выбирать между `loop`, `while` и `for`; возвращать значение из `loop` через `break`;
- [ ] управлять вложенными циклами через **метки** (`'label:`);
- [ ] понимать тип `!` («never») — тип выражений, которые не возвращают управление.

## 1. Привязки: `let` и неизменяемость по умолчанию

```rust
let x = 5;
x = 6;      // ❌ error[E0384]: cannot assign twice to immutable variable `x`
```

В Rust `let x = 5;` создаёт **неизменяемую** привязку. Это первое серьёзное расхождение с
почти всеми мейнстрим-языками:

| Язык | Умолчание | Как сделать неизменяемым |
|---|---|---|
| C / C++ | изменяемое | `const int x = 5;` (надо просить) |
| Java | изменяемое | `final int x = 5;` (надо просить) |
| Python | изменяемое | — (нет языкового способа) |
| **Rust** | **неизменяемое** | по умолчанию; `let mut` чтобы разрешить мутацию |

Умолчание перевёрнуто сознательно: неизменяемость — более безопасный и более частый случай.
Компилятор заставляет вас **явно** пометить всё, что меняется, и это документирует намерение
прямо в коде. Чтобы разрешить присваивание, добавьте `mut`:

```rust
let mut x = 5;
x = 6;          // ok
x += 1;         // ok, x == 7
```

> [!note] `mut` — это не «переменная» против «константы»
> `let x` и `let mut x` — обе привязки времени выполнения, разница лишь в том, разрешено ли
> **переприсваивание/мутация** через это имя. Настоящие константы (значения, известные на
> компиляции) — это `const`, см. §3.

### Шэдоуинг (краткий анонс)

Можно объявить `let` с тем же именем повторно — новая привязка **затеняет** старую, в том
числе с другим типом:

```rust
let spaces = "   ";        // &str
let spaces = spaces.len(); // usize — новая переменная, старая недоступна
```

Это не мутация, а новая привязка (старое значение просто перестаёт быть видимым по имени).
Подробно — в **M03**; здесь достаточно знать, что такое допустимо.

## 2. Инициализация обязательна перед использованием

Rust не имеет «значений по умолчанию» для локальных переменных (в отличие от Java, где поля
занулены, и в отличие от C, где чтение неинициализированной памяти — UB). Компилятор
статически проверяет, что к моменту чтения переменная инициализирована:

```rust
let x: i32;
println!("{x}");   // ❌ error[E0381]: used binding `x` is possibly-uninitialized
```

При этом можно объявить переменную и присвоить её позже, если компилятор может доказать, что
инициализация произойдёт ровно один раз до чтения (**отложенная инициализация**):

```rust
let x;
if cond { x = 1; } else { x = 2; }
println!("{x}");   // ok: обе ветки инициализируют x
```

Это устраняет целый класс C-багов (использование мусора из неинициализированной памяти) — но,
в отличие от C++, без затрат: проверка чисто статическая.

## 3. `const` и `static`: значения времени компиляции

```rust
const MAX_POINTS: u32 = 100_000;        // подставляется по месту использования (инлайн)
static GREETING: &str = "hello";        // единственный объект с фиксированным адресом
```

- `const` — **именованная константа**, вычисляется на компиляции и «встраивается» в каждое
  место использования (аналог C++ `constexpr`, а не рантайм-`const`). Тип указывать
  обязательно. Может стоять в любой области, включая глобальную.
- `static` — глобальная переменная с фиксированным адресом на всё время работы программы
  (`static mut` существует, но требует `unsafe` — к этому вернёмся в модулях по многопоточности
  и unsafe).

| | `let` | `const` | `static` |
|---|---|---|---|
| когда есть значение | в рантайме | на компиляции | на компиляции |
| адрес в памяти | на стеке, свой у каждого вызова | нет (инлайнится) | один на программу |
| можно `mut` | да (`let mut`) | никогда | только `static mut` + `unsafe` |
| аналог в C++ | локальная переменная | `constexpr` | глобальная переменная |

Имена констант — по конвенции `SCREAMING_SNAKE_CASE`. Разделитель `_` в числовых литералах
(`100_000`) игнорируется — чисто для читаемости.

## 4. Выражения против инструкций — сердце синтаксиса Rust

Rust — **выражение-ориентированный** язык. Различают:

- **Выражение (expression)** — вычисляется в значение и имеет тип: `5`, `x + 1`, `foo()`,
  `if c { 1 } else { 2 }`, блок `{ ... }`.
- **Инструкция (statement)** — выполняет действие, но **не имеет значения**: `let x = 5;`,
  а также любое выражение с точкой с запятой на конце.

Ключевое правило: **точка с запятой превращает выражение в инструкцию** и «выбрасывает» его
значение, подставляя вместо него `()` (пустой кортеж, «unit» — аналог `void`).

```rust
let y = {
    let a = 2;
    let b = 3;
    a + b        // без `;` — это ЗНАЧЕНИЕ блока
};               // y == 5

let z = {
    let a = 2;
    a + 3;       // с `;` — значение выброшено
};               // z == () (unit), скорее всего не то, что вы хотели
```

Блок `{ ... }` — это выражение, чьё значение равно значению **последнего выражения без `;`**.
Отсюда идиома Rust: **функция возвращает последнее выражение своего тела без `return` и без
`;`**:

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b        // никакого `return`, никакой `;`
}
```

`return` существует (для досрочного выхода), но в «хвостовой» позиции он не идиоматичен.

> [!warning] Ловушка «лишней точки с запятой»
> ```rust
> fn add(a: i32, b: i32) -> i32 {
>     a + b;     // ❌ error[E0308]: mismatched types — ожидается i32, найдено ()
> }
> ```
> С `;` тело блока имеет тип `()`, а сигнатура обещает `i32`. Это одна из самых частых ошибок
> у новичков — и компилятор ловит её сразу, в отличие от C, где `;` почти всегда безобиден.

Сравнение с C++/Java: там `if` — **инструкция** и значения не имеет (для «выражения» есть
отдельный тернарный `?:`). В Rust отдельный тернарный оператор **не нужен** — сам `if` и есть
выражение.

## 5. `if` как выражение

```rust
let n = 7;
let parity = if n % 2 == 0 { "even" } else { "odd" };   // if-выражение
```

Правила `if`-выражения:

- условие **обязано** быть `bool` — `if 1 { ... }` не скомпилируется (нет неявного приведения
  числа к логическому, как в C/C++);
- когда `if` используется как значение, **обе ветки должны иметь один тип** (иначе у выражения
  нет единого типа);
- скобки вокруг условия не нужны, фигурные скобки тела — обязательны (даже для одной строки):
  это исключает классический баг «dangling else» и `goto fail;`.

Цепочка `else if` — обычная вложенность:

```rust
let grade = if s >= 90 { 'A' } else if s >= 80 { 'B' } else { 'F' };
```

Для выбора из многих вариантов есть `match` (полноценно — в M05); он тоже выражение.

## 6. Циклы: `loop`, `while`, `for`

Rust предлагает три конструкции; выбор — по смыслу.

### `loop` — бесконечный цикл, который **возвращает значение**

```rust
let mut counter = 0;
let result = loop {
    counter += 1;
    if counter == 10 {
        break counter * 2;   // break С ЗНАЧЕНИЕМ — оно становится значением всего loop
    }
};                           // result == 20
```

`loop { ... }` — единственный цикл, который является полноценным выражением с результатом:
`break value;` задаёт значение всего `loop`. В C/C++/Java такого нет — там пришлось бы завести
внешнюю переменную. `loop` идеально подходит для «повторяй, пока не найдёшь, потом верни».

### `while` — цикл с предусловием

```rust
while n != 1 {
    n = if n % 2 == 0 { n / 2 } else { 3 * n + 1 };
}
```

Как в других языках. Значения не возвращает (тип `()`).

### `for` — итерация по итератору (то, что в C++ называют range-based for)

```rust
for i in 0..5 {          // 0,1,2,3,4  — 0..5 полуоткрытый диапазон (Range)
    print!("{i} ");
}
for i in 1..=5 { }       // 1,2,3,4,5  — 1..=5 включает конец
for x in [10, 20, 30] { }// по элементам массива
```

`for` в Rust — **всегда по итератору**, а не «счётчик с условием». Классический C-цикл
`for (int i=0;i<n;i++)` пишется как `for i in 0..n`. Это безопаснее (нельзя выйти за границу
и промахнуться мимо условия) и идиоматичнее; полноценно итераторы — в M19.

Управление ходом цикла: `break` (выйти), `continue` (к следующей итерации) — в любом из трёх.

## 7. Метки циклов (`'label`)

`break`/`continue` по умолчанию относятся к **ближайшему** циклу. Чтобы управлять внешним из
вложенного, цикл помечают меткой с апострофом:

```rust
'outer: for i in 0..height {
    for j in 0..width {
        if grid[i][j] == target {
            break 'outer;    // выходим сразу из внешнего цикла
        }
    }
}
```

Метка сочетается и с возвратом значения: `break 'outer value;`. В C/C++ то же самое делают
через `goto` или флаг-переменную; метки Rust структурированы и не дают «прыгнуть куда угодно».

## 8. Тип `!` — «never» (расходящиеся выражения)

Некоторые выражения **никогда не возвращают управление**: `panic!(...)`, `unreachable!()`,
бесконечный `loop {}` без `break`, `std::process::exit(...)`, `return`/`break`/`continue` как
выражения. Их тип — `!` («never type»), особенный тем, что **приводится к любому типу**.

Зачем это нужно на практике — чтобы такие выражения можно было ставить в позицию, где ожидается
конкретный тип, и ветвь при этом «не мешала» выводу типа:

```rust
let x: i32 = if ok { 42 } else { panic!("нет значения") };
//                    ^^ i32           ^^^^^^^^^ тип !, подстраивается под i32

let bit: u8 = match c {
    '0' => 0,
    '1' => 1,
    _   => unreachable!(),   // тип !, не ломает требование «все ветки одного типа»
};
```

Обе ветки `if`/`match` формально «одного типа» именно потому, что `!` совместим с `i32`/`u8`.
В C++ прямого аналога нет (есть атрибут `[[noreturn]]`, но это не полноправный тип). Понимание
`!` пригодится в модуле про обработку ошибок (M16), где `?` и `panic!` встречаются постоянно.

## 9. Тизер к M02

Мы научились связывать значения и управлять потоком, но обращались с типами поверхностно
(`i32`, `bool`, `char`). Следующий модуль — **скалярные и составные типы**: целые разных
разрядностей и что происходит при **переполнении** (в отладке — паника, в релизе — обёртка),
`f64`, `char` как Unicode scalar value, кортежи, массивы и **срезы**. Там же — почему
`0..5` имеет тип `Range<i32>` и как это связано с `for`.
