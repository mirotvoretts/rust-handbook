# M18 — Замыкания

> Часть VI «Коллекции, замыкания, итераторы». Предыдущий модуль: [M17 Коллекции](../17-collections/README.md).
> Дальше: [M19 Итераторы](../19-iterators/README.md).

## Цель модуля

Замыкание — это **анонимная структура с окружением плюс код**. Разобрав его до
винтиков, вы поймёте тройку `Fn`/`FnMut`/`FnOnce` (почему `sort_by_key` хочет
`FnMut`, а `thread::spawn` — `FnOnce`), научитесь предсказывать способ захвата
каждой переменной и перестанете воевать с `move`.

После модуля вы умеете:

- [ ] написать «десахаризацию» замыкания: структура захватов + impl Fn-трейта;
- [ ] объяснить иерархию `Fn: FnMut: FnOnce` и выбрать правильную границу для
      своего API;
- [ ] предсказать способ захвата каждой переменной (`&T` / `&mut T` / `T`) по телу;
- [ ] применять `move` осознанно — и знать, когда без него не скомпилируется;
- [ ] принимать замыкания в функции (дженерик) и возвращать их (`impl Fn`);
- [ ] отличать замыкание от указателя на функцию `fn(T) -> R`.

## 1. Замыкание = структура + impl

```rust
let base = 10;
let add_base = |x: i32| x + base;    // захватил base
add_base(5);                          // 15
```

Компилятор генерирует примерно это:

```rust
struct AddBase<'a> { base: &'a i32 }              // окружение: захваты как поля

impl<'a> Fn... for AddBase<'a> {                  // вызов — через Fn-трейт
    fn call(&self, (x,): (i32,)) -> i32 { x + *self.base }
}
```

Следствия, которые объясняют всё дальнейшее:

- у **каждого** замыкания свой уникальный, невыразимый тип (поэтому «вернуть
  замыкание» — это `impl Fn`, M15, а «хранить разные» — `Box<dyn Fn>`, M14);
- замыкание без захватов — ZST, ничего не весит;
- захваты — обычные поля: к ним применяются все правила владения и займов из
  M06–M07. «Магии» нет — есть скрытая структура.

## 2. Тройка `Fn` / `FnMut` / `FnOnce`

Оператор вызова `()` — тоже трейт (как `+` в M13). Их три, по способу доступа к
окружению:

```rust
trait FnOnce<Args> { type Output; fn call_once(self, ...) -> Self::Output; }
trait FnMut<Args>: FnOnce<Args>  { fn call_mut(&mut self, ...) -> ...; }
trait Fn<Args>:    FnMut<Args>   { fn call(&self, ...) -> ...; }
```

| Трейт | self | Сколько раз можно звать | Что делает с окружением |
|---|---|---|---|
| `FnOnce` | `self` | один | может **потребить** захваты |
| `FnMut` | `&mut self` | много | может **менять** захваты |
| `Fn` | `&self` | много | только **читает** захваты |

Иерархия `Fn ⊂ FnMut ⊂ FnOnce`: всё, что можно звать по `&self`, можно звать и по
`&mut self`, и по `self`. Компилятор реализует для замыкания **максимально сильный**
из подходящих трейтов, глядя на тело:

```rust
let read  = || println!("{}", data.len());   // Fn (+ FnMut + FnOnce)
let write = || data.push(1);                 // FnMut (+ FnOnce)
let eat   = || drop(data);                   // только FnOnce: data потреблена
```

### Выбор границы в API

Правило: **требуйте самый слабый трейт, достаточный телу** — так вы принимаете
максимум замыканий:

```rust
fn map<T, R, F: FnMut(&T) -> R>(xs: &[T], mut f: F) -> Vec<R> { ... }
//        ^^^ FnMut: зовём многократно, разрешаем мутирующие счётчики
//            (с FnOnce цикл не скомпилируется: второй вызов = use after move)
```

Ориентиры из std: `sort_by_key` — `FnMut` (много вызовов), `Option::map` — `FnOnce`
(один вызов, можно потребить захваты), `thread::spawn` — `FnOnce` (вызов один, и
замыкание уедет в другой поток).

## 3. Вывод захватов

Способ захвата **каждой** переменной компилятор выбирает по её использованию в теле
— минимально достаточный:

```rust
let xs = vec![1, 2, 3];
let ys = vec![4, 5, 6];
let mut zs = vec![7, 8, 9];

let f = || {
    println!("{}", ys.len());   // ys — по &T (только чтение)
    zs.push(10);                // zs — по &mut T (мутация)
    drop(xs);                   // xs — по значению T (потребление)
};
```

Скрытая структура: `{ ys: &Vec<i32>, zs: &mut Vec<i32>, xs: Vec<i32> }`. Пока `f`
жива, `ys` заимствована, `zs` — эксклюзивно, `xs` — перемещена: borrow checker
применяет к замыканию обычные правила M07. Отсюда классика:

```rust
let f = || zs.push(1);
// zs.push(2);       // ❌ E0499: zs уже занята замыканием (&mut)
f();
zs.push(2);          // ok: f больше не используется, заём кончился (NLL)
```

Сравнение с C++: там способ захвата пишут руками (`[=]`, `[&]`, `[x = std::move(y)]`)
и можно молча захватить висячую ссылку; Rust выводит захваты сам и **проверяет**
их корректность.

## 4. `move`: захват по значению принудительно

Иногда вывод «по ссылке» не годится — замыкание переживёт окружение:

```rust
fn make_counter() -> impl FnMut() -> u32 {
    let mut count = 0;
    move || { count += 1; count }   // без move: заём на локальную count — E0373
}
```

`move` меняет **способ захвата** (всё — по значению), но не Fn-трейт: тот по-прежнему
определяется телом. `move`-замыкание, только читающее захваты, — всё ещё `Fn`.

Когда `move` обязателен: возврат замыкания из функции, передача в поток
(`thread::spawn`, M22), хранение в структуре, живущей дольше окружения. Тонкость:
для `Copy`-типов `move` копирует — оригинал остаётся доступным; для остальных —
перемещает.

Нужно смешать (это по значению, то по ссылке) — перепривяжите заранее:

```rust
let ys_ref = &ys;
let f = move || { drop(xs); println!("{}", ys_ref.len()) };  // xs по значению, ys через &
```

## 5. Указатели на функции

Обычная функция тоже реализует Fn-трейты, но у неё есть и **записываемый** тип —
указатель `fn(T) -> R` (маленькая f!):

```rust
fn double(x: i32) -> i32 { x * 2 }
fn negate(x: i32) -> i32 { -x }

let ops: Vec<fn(i32) -> i32> = vec![double, negate];   // однородный вектор — ок
```

| | замыкание | `fn`-указатель |
|---|---|---|
| тип | уникальный, невыразимый | записываемый `fn(T) -> R` |
| окружение | есть | нет |
| размер | размер захватов (0 для пустых) | usize (адрес) |
| в Vec без Box | только одинаковые | любые с одной сигнатурой |

Замыкание **без захватов** приводится к `fn`-указателю: `let p: fn(i32) -> i32 =
|x| x + 1;`. С захватами — нет (окружение некуда деть).

## 6. Замыкания и владение: типовые грабли

```rust
// 1. Потребляющее замыкание нельзя позвать дважды
let s = String::from("hi");
let eat = move || s;          // FnOnce
eat();
// eat();                     // ❌ use of moved value

// 2. FnMut требует mut-привязки
let mut counter = make_counter();
counter();                    // без `mut counter` — E0596

// 3. Замыкание в цикле: каждая итерация — свой захват
let mut handlers = Vec::new();
for k in 0..3 {
    handlers.push(move |x: i32| x + k);   // k копируется (i32: Copy) в каждое
}
```

## 7. Тизер к M19

Замыкания — топливо итераторов: `map(|x| ...)`, `filter(|x| ...)` хранят ваше
замыкание в поле структуры-адаптера и вызывают через `FnMut`. Следующий модуль —
**итераторы**: трейт `Iterator`, ленивость («адаптеры ничего не делают»), почему
цепочка `.map().filter().sum()` компилируется в цикл без аллокаций, и как написать
свой итератор.
