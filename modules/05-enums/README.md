# M05 - Перечисления и сопоставление с образцом

> Часть I "Основы языка". Предыдущий модуль: [M04 Структуры и методы](../04-structs/README.md).

## Цель модуля

Освоить **перечисления** (`enum`) - способ сказать "значение бывает **одного из** нескольких
видов", и **сопоставление с образцом** (`match`) - способ разобрать его по видам с проверкой
полноты на компиляции. Enum в Rust - это не "пронумерованные константы", как в C, а
**алгебраический тип-сумма** (safe tagged union): каждый вариант может нести **свои данные**.
На этом фундаменте построены `Option` (замена `null`) и `Result` (обработка ошибок).

После модуля вы умеете:

- [ ] объявлять enum с вариантами без данных, с кортежными и структурными данными;
- [ ] разбирать значение через `match` - исчерпывающе, с деструктуризацией и связыванием;
- [ ] использовать диапазоны, or-паттерны `|`, guard-условия и связывание `@`;
- [ ] применять `if let` / `while let` / `let ... else` для частных случаев;
- [ ] работать с `Option<T>` вместо `null` и с `Result<T, E>` для ошибок.

## 1. Enum - тип-сумма

```rust
enum Direction {
    North,
    East,
    South,
    West,
}

let d = Direction::North;
```

Пока это похоже на C-шный `enum`. Но в Rust варианты могут **нести данные**, причём разного
вида для каждого варианта:

```rust
enum Shape {
    Circle(f64),                       // кортежный вариант: радиус
    Rectangle(f64, f64),               // ширина, высота
    Triangle { base: f64, height: f64 },// структурный вариант
    Unit,                              // вариант без данных
}
```

Значение типа `Shape` - это **ровно один** из вариантов вместе с его данными. Это и есть
тип-сумма ("Circle ИЛИ Rectangle ИЛИ ..."), в отличие от структуры-произведения из M04
("поле И поле И ...").

> [!note] Rust enum против C enum и union
> - В C `enum` - это просто именованные `int`-константы; данные к ним не привязать.
> - Носитель "одно из с данными" в C - это `union` + отдельный тег-поле, и компилятор **не
>   следит**, что вы читаете `union` через правильный член: прочитать не тот - UB.
> - Rust enum объединяет тег и данные в **один безопасный тип**: невозможно прочитать данные
>   "не того" варианта - `match` заставляет сначала проверить, какой это вариант. Это tagged
>   union, корректность которого гарантирована системой типов.

Размер enum = размер тега + размер наибольшего варианта (есть нишевые оптимизации, п.7).
Enum'у можно давать методы через `impl`, как структурам.

## 2. `match` - исчерпывающий разбор

```rust
fn opposite(d: Direction) -> Direction {
    match d {
        Direction::North => Direction::South,
        Direction::East => Direction::West,
        Direction::South => Direction::North,
        Direction::West => Direction::East,
    }
}
```

Свойства `match`:

- Это **выражение** - возвращает значение, все ветки одного типа (как `if`, M01).
- **Исчерпывающий**: компилятор требует покрыть **все** варианты. Забыли `West` - ошибка
  компиляции `non-exhaustive patterns`. Это ловит баги при добавлении нового варианта: код,
  который его не обработал, **не соберётся**. В C `switch` без `default` молча пропустит
  неучтённый случай.
- `_` - "всё остальное" (wildcard), ставится последним для сборной ветки.

### Деструктуризация в ветках

`match` не только выбирает ветку, но и **извлекает** данные варианта, связывая их с именами:

```rust
fn area(shape: &Shape) -> f64 {
    match shape {
        Shape::Circle(r) => std::f64::consts::PI * r * r,
        Shape::Rectangle(w, h) => w * h,
        Shape::Triangle { base, height } => 0.5 * base * height,
        Shape::Unit => 0.0,
    }
}
```

## 3. Богатые паттерны: диапазоны, `|`, guard, `@`

```rust
fn grade(score: u32) -> char {
    match score {
        90..=100 => 'A',        // диапазон (inclusive)
        80..=89 => 'B',
        70..=79 => 'C',
        60..=69 => 'D',
        _ => 'F',
    }
}

fn is_vowel(c: char) -> bool {
    matches!(c, 'a' | 'e' | 'i' | 'o' | 'u')   // or-паттерн `|`
}

fn classify(n: i32) -> &'static str {
    match n {
        0 => "zero",
        n if n < 0 => "negative",   // guard: условие поверх паттерна
        _ => "positive",
    }
}
```

- **Диапазон** `1..=5` в паттерне матчит любое значение из отрезка.
- **Or-паттерн** `A | B` матчит несколько альтернатив в одной ветке.
- **Guard** `паттерн if условие` - дополнительная проверка; ветка срабатывает, только если
  условие истинно (на исчерпывающность guard не влияет - компилятор его "не считает").
- **Связывание `@`**: `n @ 1..=5` - проверить диапазон И привязать значение к имени `n`.
- `matches!(value, pattern)` - макрос-сокращение для `match value { pattern => true, _ => false }`.

## 4. `if let`, `while let`, `let ... else`

Когда интересен **один** вариант, полный `match` избыточен. `if let` - "частичный match":

```rust
if let Some(n) = opt {
    println!("есть значение: {n}");
} else {
    println!("пусто");
}
```

`while let` крутит цикл, пока паттерн совпадает - идеально для "вычерпывания" контейнера:

```rust
let mut stack = vec![1, 2, 3];
while let Some(top) = stack.pop() {   // пока pop() возвращает Some
    println!("{top}");
}
```

`let ... else` привязывает при совпадении, иначе выполняет расходящуюся ветку (обычно `return`):

```rust
let Some(n) = opt else {
    return 0;      // ветка else обязана расходиться (!)
};
// здесь n доступно
```

## 5. `Option<T>` - вместо `null`

`Option` - обычный enum из стандартной библиотеки:

```rust
enum Option<T> {
    Some(T),
    None,
}
```

Он выражает "значение **есть или его нет**" на уровне типа. В Rust **нет `null`**: ссылка `&T`
всегда валидна, а "может отсутствовать" кодируется как `Option<&T>`. Компилятор заставляет
обработать случай `None` (через `match`/`if let`), поэтому нельзя случайно разыменовать
"ничего".

```rust
fn first(xs: &[i32]) -> Option<i32> {
    if xs.is_empty() { None } else { Some(xs[0]) }
}

match first(&data) {
    Some(x) => println!("первый: {x}"),
    None => println!("пусто"),
}
```

Полезные комбинаторы (подробно - M16): `.map(f)`, `.unwrap_or(default)`, `.filter(pred)`,
`.and_then(f)`, `.is_some()`.

> [!warning] "Ошибка на миллиард долларов"
> Тони Хоар назвал изобретение `null` своей "ошибкой на миллиард долларов": в C/C++/Java любой
> указатель/ссылка может неожиданно оказаться `null`, и разыменование - крах или UB. `Option`
> переносит эту возможность **в тип**: если значение может отсутствовать, это видно в сигнатуре
> `Option<T>`, и компилятор не даст забыть про `None`. Целый класс NPE исчезает на компиляции.

## 6. `Result<T, E>` - для ошибок

```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}

fn checked_div(a: i32, b: i32) -> Result<i32, String> {
    if b == 0 {
        Err(String::from("cannot divide by zero"))
    } else {
        Ok(a / b)
    }
}
```

`Result` - тип-сумма "успех `Ok(T)` **или** ошибка `Err(E)`". Ошибки в Rust - это **значения**,
которые возвращаются и обрабатываются через `match`, а не исключения, летящие мимо сигнатур
(как в C++/Java). Функция, которая может дать сбой, **честно** пишет это в своём типе
возврата. Полноценно - модуль M16 (там же оператор `?`, свои типы ошибок, `panic!`).
