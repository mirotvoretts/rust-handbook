# M03 - Функции и ссылки (введение)

> Часть I "Основы языка". Предыдущий модуль: [M02 Скалярные и составные типы](../02-scalar-compound/README.md).

## Цель модуля

Научиться писать функции и **передавать данные без передачи владения** - через ссылки `&T`
(заём для чтения) и `&mut T` (заём для изменения). Это первое знакомство с заимствованием:
полностью правила borrow-checker'а мы разберём в **M07**, здесь - только практический минимум,
чтобы функции могли читать и менять данные, не забирая их себе. Плюс закроем тему **shadowing**,
анонсированную в M01.

После модуля вы умеете:

- [ ] объявлять функции, указывать типы параметров и возврата, использовать ранний `return`;
- [ ] отличать передачу **по значению** (move/copy) от передачи **по ссылке**;
- [ ] брать `&T`, разыменовывать через `*`, и понимать, зачем это вместо `.clone()`;
- [ ] менять данные через `&mut T` и `&mut [T]`, не возвращая новое значение;
- [ ] применять **shadowing** и объяснять, чем он отличается от `mut`.

## 1. Функции

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

- Имена - `snake_case` (проверяется линтером).
- **Типы параметров указывать обязательно** (в отличие от вывода типа для локальных `let`):
  сигнатура функции - это контракт, компилятор не угадывает типы аргументов.
- Тип возврата после `->`; если его нет, функция возвращает **unit** `()` (аналог `void`).
- Тело - блок-выражение: значение последнего выражения без `;` и есть результат (см. M01).
- `return expr;` - досрочный выход; в хвостовой позиции не идиоматичен.

```rust
fn abs_val(n: i32) -> i32 {
    if n < 0 {
        return -n;      // ранний выход
    }
    n                   // хвостовое значение
}
```

> [!note] Порядок объявления не важен
> В C нужно объявить функцию (или прототип) до вызова; в C++ - тоже (либо forward declaration).
> В Rust функции модуля видны целиком, независимо от порядка: `main` может вызвать `helper`,
> объявленный ниже. Никаких заголовочных файлов и прототипов.

## 2. Передача по значению против ссылки

Передача аргумента - это, по умолчанию, **move** (для не-`Copy` типов) или **copy** (для
`Copy`): п.M06/M01. Значит, если передать `String` по значению, вызывающий её **теряет**:

```rust
fn len_of(s: String) -> usize { s.len() }

let s = String::from("hi");
let n = len_of(s);     // s перемещён в функцию...
// println!("{s}");    // [!] s больше недоступен
```

Часто это не то, что нужно: функции достаточно **посмотреть** на данные, а владение пусть
остаётся у вызывающего. Для этого берут **ссылку**:

```rust
fn len_of(s: &String) -> usize { s.len() }

let s = String::from("hi");
let n = len_of(&s);    // одолжили доступ...
println!("{s}");        // [+] s всё ещё наш
```

**Ссылка (reference)** `&T` - не владеющий указатель на существующее значение. `&x` создаёт
ссылку ("заём"), `*r` - разыменование (доступ к значению по ссылке). Для вызова методов
разыменование обычно **автоматическое**: `r.len()` вместо `(*r).len()`.

```rust
fn deref_sum(a: &i32, b: &i32) -> i32 {
    *a + *b            // явное разыменование для арифметики
}
```

> [!note] Ссылки Rust против указателей C и ссылок C++
> - В C `T*` может быть нулевым и указывать в никуда. Ссылка Rust `&T` **всегда валидна и
>   не-нулева** - компилятор это гарантирует (висячая ссылка = ошибка компиляции, не UB).
> - Ссылка C++ `T&` тоже не-нулева, но не отслеживает время жизни: можно вернуть ссылку на
>   локальную переменную и получить UB. Rust такое не пропустит (см. времена жизни, M08).

## 3. Изменяемые ссылки `&mut T`

Чтобы функция **меняла** переданное значение на месте (а не возвращала новое), берут
изменяемую ссылку `&mut T` и пишут через `*`:

```rust
fn increment(n: &mut i32) {
    *n += 1;           // меняем то, на что ссылаемся
}

let mut x = 5;         // связывание должно быть mut...
increment(&mut x);     // ...и заём берём как &mut
assert_eq!(x, 6);
```

Три условия, чтобы это скомпилировалось: переменная объявлена `let mut`, ссылка взята как
`&mut x`, параметр имеет тип `&mut T`. Это Rust-замена "выходным параметрам" C (`void f(int*
out)`) - но безопасная: нельзя передать нулевой или невалидный указатель.

> [!warning] Правило, которое мы раскроем в M07
> Пока существует `&mut T` на значение, **никаких других ссылок** (ни `&`, ни `&mut`) на него
> быть не может - "одна изменяемая ИЛИ много неизменяемых" (shared XOR mutable). Это и ловит
> на компиляции целый класс багов (гонки, инвалидация итераторов). Здесь мы почти не столкнёмся
> с ограничением, но знать о нём полезно.

Ссылки на срезы тоже бывают изменяемыми - `&mut [T]` позволяет менять элементы
последовательности на месте:

```rust
fn fill(xs: &mut [i32], value: i32) {
    for x in xs.iter_mut() {
        *x = value;
    }
}
```

## 4. Shadowing (затенение)

Можно объявить `let` с уже занятым именем - возникает **новая** переменная, затеняющая
предыдущую. В отличие от `mut`, это не мутация, а **новое связывание**, и оно может **менять
тип**:

```rust
let spaces = "   ";        // &str
let spaces = spaces.len(); // usize - новая переменная того же имени
```

Классическое применение - переиспользовать удачное имя после преобразования, не заводя
`spaces_str`/`spaces_num`:

```rust
fn trimmed_len(s: &str) -> usize {
    let s = s.trim();      // s: &str (без пробелов по краям)
    let s = s.chars().count(); // s: usize - тип сменился
    s
}
```

### Shadowing против `mut`

| | `let mut x` затем `x = ...` | `let x` затем `let x = ...` |
|---|---|---|
| что это | мутация того же значения | новое связывание, старое затенено |
| смена типа | [!] нельзя (тип фиксирован) | [+] можно |
| неизменяемость результата | остаётся `mut` | снова неизменяемое |
| область | до конца области | до следующего затенения/конца области |

Shadowing уважает области видимости: тень, созданная во внутреннем блоке `{ ... }`, исчезает
на выходе, и снаружи снова видно исходное значение. Ни в C, ни в C++, ни в Java нет
затенения в пределах **одной** области с этой семантикой (там повторное объявление в той же
области - ошибка); Rust позволяет это осознанно.
