# M04 - Структуры и методы

> Часть I "Основы языка". Предыдущий модуль: [M03 Функции и ссылки](../03-functions-refs/README.md).

## Цель модуля

Научиться описывать **свои типы-данные** структурами и присоединять к ним **поведение** через
`impl`-блоки. Ключевое отличие от ООП C++/Java: в Rust **данные и поведение объявляются
раздельно** (`struct` отдельно, `impl` отдельно), **нет наследования**, а вместо неявного
`this` - явный первый параметр `self` в одной из трёх форм. Это модель "данные + методы",
а не "класс с виртуальными таблицами".

После модуля вы умеете:

- [ ] объявлять структуры с именованными полями, tuple-структуры, newtype и unit-структуры;
- [ ] создавать значения, читать поля, использовать сокращённую инициализацию и `..`-обновление;
- [ ] писать методы в трёх формах `self`: `&self`, `&mut self`, `self` - и понимать, какую выбрать;
- [ ] писать ассоциированные функции (`Type::new`) - Rust-аналог статических методов/конструкторов;
- [ ] выводить типажи через `#[derive(...)]` (`Debug`, `PartialEq`, `Clone`, `Copy`).

## 1. Структуры с именованными полями

```rust
struct User {
    name: String,
    age: u32,
    active: bool,
}

let u = User {
    name: String::from("Аня"),
    age: 30,
    active: true,
};
println!("{}", u.age);      // доступ к полю через точку
```

- Экземпляр создаётся перечислением **всех** полей (частичная инициализация запрещена).
- Чтобы менять поля, **вся переменная** должна быть `mut` (нельзя пометить отдельное поле
  изменяемым - в отличие от C++ `mutable`): `let mut u = ...; u.age += 1;`.
- Порядок полей при создании не важен, но обычно пишут как в объявлении.

### Сокращения

```rust
fn build(name: String, age: u32) -> User {
    User { name, age, active: true }   // field init shorthand: `name` вместо `name: name`
}

let older = User { age: 31, ..u };     // struct update: остальные поля взять из `u`
```

**Field init shorthand**: если локальная переменная называется как поле, пишут просто её имя.
**Struct update syntax** `..base`: заполнить недостающие поля из другого экземпляра (поля
**перемещаются** из `base`, если они не `Copy`, - `base` после этого частично перемещён).

## 2. Tuple-структуры, newtype и unit-структуры

```rust
struct Point(i32, i32);        // tuple-структура: поля без имён, доступ по .0/.1
let p = Point(3, 4);
let x = p.0;

struct Meters(f64);            // newtype: обёртка над одним типом
struct Marker;                 // unit-структура: без полей вообще
```

- **Tuple-структура** - как кортеж, но с собственным именем типа; поля по индексам `.0`, `.1`.
- **Newtype** (частный случай tuple-структуры с одним полем) - обёртка, дающая **новый тип**
  поверх существующего. Зачем: `Meters(f64)` и `Feet(f64)` - разные типы, компилятор не даст их
  перепутать, хотя внутри оба `f64`. Это дешёвая (zero-cost) типобезопасность, которой нет в C
  с его `typedef` (там `typedef double Meters;` не создаёт нового типа).
- **Unit-структура** - без данных; полезна как маркер или носитель поведения (пригодится с
  трейтами, M12).

## 3. Методы и формы `self`

Поведение присоединяется в блоке `impl`:

```rust
struct Rectangle { width: u32, height: u32 }

impl Rectangle {
    fn area(&self) -> u32 {           // &self - читает
        self.width * self.height
    }
    fn scale(&mut self, k: u32) {     // &mut self - изменяет
        self.width *= k;
        self.height *= k;
    }
    fn into_pair(self) -> (u32, u32) {// self - потребляет (забирает владение)
        (self.width, self.height)
    }
}

let mut r = Rectangle { width: 3, height: 4 };
r.area();          // 12
r.scale(2);        // r теперь 6x8
let pair = r.into_pair();  // r потреблён, дальше недоступен
```

`self` - это первый параметр метода, и он бывает трёх форм. Выбор - по тому, что метод делает
с объектом:

| Форма | Полное написание | Смысл | Когда |
|---|---|---|---|
| `&self` | `self: &Self` | заём для чтения | метод только читает поля |
| `&mut self` | `self: &mut Self` | заём для изменения | метод меняет поля |
| `self` | `self: Self` | забирает владение | метод потребляет/преобразует объект |

Вызов `r.area()` - это синтаксический сахар для `Rectangle::area(&r)`: Rust **автоматически**
берёт `&`/`&mut` или перемещает по нужной форме `self` (auto-ref). Явного `this`, как в C++,
и стрелочного `->` из C нет - точка работает и для значения, и для ссылки.

> [!note] Данные и поведение - раздельно; наследования нет
> В C++/Java данные и методы лежат внутри `class`. В Rust `struct` описывает **только данные**,
> `impl` - **только поведение**, и их может быть несколько (в т.ч. для чужих типов через
> трейты, M12). **Наследования классов нет вообще**: повторное использование достигается
> композицией и трейтами, а не деревом базовых классов. Это осознанный отказ от проблем
> хрупкого базового класса и ромбовидного наследования.

## 4. Ассоциированные функции

Функция в `impl` **без** `self` - ассоциированная (вызывается через `Type::`), Rust-аналог
статического метода. По конвенции конструктор называют `new`:

```rust
impl Rectangle {
    fn new(width: u32, height: u32) -> Self {   // Self == Rectangle
        Rectangle { width, height }
    }
    fn square(size: u32) -> Self {
        Rectangle { width: size, height: size }
    }
}

let r = Rectangle::new(3, 4);
let s = Rectangle::square(5);
```

`Self` (с большой буквы) - псевдоним типа, которому принадлежит `impl`. У Rust **нет
специальных конструкторов** с магическим синтаксисом (как в C++/Java): `new` - обычная
функция по договорённости, ничего не мешает назвать её иначе или иметь несколько
(`from_str`, `with_capacity`, `square`). Блоков `impl` может быть несколько.

## 5. Вывод типажей через `#[derive(...)]`

Многие стандартные возможности можно **сгенерировать** атрибутом `derive`:

```rust
#[derive(Debug, Clone, PartialEq)]
struct Point { x: i32, y: i32 }

let a = Point { x: 1, y: 2 };
let b = a.clone();
assert_eq!(a, b);                  // PartialEq -> работает ==
println!("{a:?}");                 // Debug -> "Point { x: 1, y: 2 }"
println!("{a:#?}");                // pretty-print с отступами
```

| derive | Что даёт |
|---|---|
| `Debug` | форматирование `{:?}`/`{:#?}` для отладки |
| `Clone` | метод `.clone()` (глубокая копия) |
| `Copy` | побитовое копирование вместо move (только если все поля `Copy`) |
| `PartialEq` | операторы `==` / `!=` |
| `PartialOrd`, `Ord` | сравнения `<`, `>`, сортировка |
| `Default` | `Type::default()` со значениями по умолчанию |

`derive` - это макрос, разворачивающийся в обычный `impl` соответствующего трейта (подробно -
M13 про операторы и M31 про derive-макросы). Пока достаточно воспринимать его как "сгенерируй
очевидную реализацию".

## 6. Тизер к M05

Структура - это "И"-тип: `User` содержит имя **и** возраст **и** флаг одновременно
(произведение типов). Но часто нужен "ИЛИ"-тип: значение - это **либо** одно, **либо** другое
(сумма типов). Следующий модуль - **перечисления** (`enum`) и **сопоставление с образцом**
(`match`): как Rust моделирует "одно из" и почему `Option`/`Result` - это обычные enum'ы, а не
встроенная магия.
