# M10 — Модули, пути и крейты

> Часть III «Проект». Предыдущий модуль: [M09 Времена жизни II](../09-lifetimes-2/README.md).
> Дальше: Часть IV — [M11 Дженерики](../11-generics/README.md).

## Цель модуля

Научиться организовывать код: делить его на **модули**, управлять **видимостью** (`pub` и его
разновидности), обращаться к элементам по **путям**, импортировать их через `use` и понимать,
что такое **крейт**, **пакет** и **cargo-зависимости**. Здесь Rust решает те же задачи, что в
C++ решают заголовки, `namespace`, include guards и CMake, — но принципиально иначе: **никаких
заголовочных файлов, forward-declaration и ODR**.

После модуля вы умеете:

- [ ] объявлять модули (`mod`) — встроенные и файловые — и понимать дерево модулей;
- [ ] обращаться к элементам по абсолютным (`crate::`) и относительным (`super::`/`self::`) путям;
- [ ] управлять видимостью: `pub`, `pub(crate)`, `pub(super)`, приватность по умолчанию;
- [ ] импортировать пути через `use` (с `as`, `{}`, `*`) и делать ре-экспорт `pub use`;
- [ ] отличать пакет, крейт (бинарный/библиотечный), workspace; подключать зависимости.

## 1. Пакет, крейт, crate root

- **Крейт (crate)** — минимальная единица компиляции. Бывает **библиотечным** (`lib.rs`) или
  **бинарным** (`main.rs`). Компилятор `rustc` компилирует крейт целиком за раз.
- **Пакет (package)** — то, что описано одним `Cargo.toml`: один или несколько крейтов
  (максимум одна библиотека + сколько угодно бинарников).
- **Crate root** — корневой файл: `src/lib.rs` (библиотека) или `src/main.rs` (бинарник). С
  него компилятор начинает строить дерево модулей.

В этом курсе каждое упражнение — это **библиотечный крейт** (`lib.rs`), а тесты в `tests/` —
отдельный крейт, который видит только **публичный** API упражнения (это и делает `pub` важным).

---

## 2. Модули

Модуль — именованное пространство, группирующее элементы (функции, типы, другие модули).
Объявляется `mod`:

```rust
mod arithmetic {           // встроенный (inline) модуль
    pub fn add(a: i32, b: i32) -> i32 { a + b }

    pub mod advanced {     // вложенный модуль
        pub fn square(n: i32) -> i32 { n * n }
    }
}
```

Модуль можно вынести в **файл**: `mod arithmetic;` в crate root ищет `src/arithmetic.rs` (или
`src/arithmetic/mod.rs`). Так строится **дерево модулей** с корнем `crate`:

```
crate
└── arithmetic
    ├── add
    └── advanced
        └── square
```

В отличие от C++, модуль — это **языковая** сущность, не связанная с файлами напрямую: `mod` в
одном файле создаёт вложенность независимо от файловой раскладки. Никаких `#include`, порядок
объявлений внутри крейта не важен (forward-declaration не нужны).

---

## 3. Пути

Элемент адресуется **путём** — абсолютным или относительным:

```rust
crate::arithmetic::add(1, 2);          // абсолютный: от корня крейта
self::add(1, 2);                        // относительный: от текущего модуля
super::sibling::helper();               // относительный: от родительского модуля
```

- `crate::` — от корня текущего крейта (абсолютный путь).
- `self::` — от текущего модуля.
- `super::` — от родительского модуля (аналог `../` в файловой системе).

Это соответствует C++ `::foo` (глобальный), `foo` (текущий), но `super::` прямого аналога не
имеет — в C++ вложенные `namespace` так «вверх» не адресуют.

---

## 4. Видимость: приватность по умолчанию

**Всё приватно по умолчанию** — элемент виден только в своём модуле и его **потомках**. Чтобы
открыть его наружу (родителю и дальше), нужен `pub`:

```rust
mod bank {
    pub struct Account {   // тип публичен...
        balance: u64,      // ...но поле приватно: снаружи не прочитать напрямую
    }
    impl Account {
        pub fn new(initial: u64) -> Account { Account { balance: initial } }
        pub fn balance(&self) -> u64 { self.balance }   // доступ через метод
    }
}
```

Градации видимости:

| Запись | Видно |
|---|---|
| (по умолчанию) | только в этом модуле и его потомках |
| `pub` | всем, кто видит сам модуль |
| `pub(crate)` | везде внутри текущего крейта, но не снаружи |
| `pub(super)` | в родительском модуле (и его потомках) |
| `pub(in путь)` | в указанном предке-модуле |

Тонкости:

- **Поля структуры приватны по умолчанию**, даже если сама структура `pub` (инкапсуляция как в
  C++ `class` с `private`). Открываются пометкой `pub` на поле.
- **Варианты enum наследуют видимость enum**: если `enum` публичен, все его варианты и их
  поля публичны (в отличие от структур).
- Потомок видит приватные элементы предков; предок приватные элементы потомка — нет.

> [!note] Приватность защищает инварианты
> Приватное поле `balance` нельзя изменить снаружи в обход методов — значит, инварианты (баланс
> не уходит в минус и т.п.) гарантированы. Это тот же принцип инкапсуляции, что в C++, но
> **границей выступает модуль**, а не класс: всё в одном модуле видит приватные поля друг друга.

## 5. `use` — импорт путей в область видимости

`use` вводит путь в текущую область, чтобы не писать его целиком:

```rust
use crate::arithmetic::advanced::square;
use std::collections::HashMap;

square(5);                       // вместо crate::arithmetic::advanced::square(5)
```

Варианты:

```rust
use std::cmp::{min, max};        // несколько имён из одного модуля
use std::io::Result as IoResult; // переименование при импорте
use std::collections::*;         // glob: всё публичное (обычно не злоупотреблять)
```

**Ре-экспорт** `pub use` делает импортированное имя частью **своего** публичного API — так
строят удобный «фасад», пряча внутреннюю структуру модулей:

```rust
mod internal { pub fn compute(n: i32) -> i32 { n + 100 } }
pub use internal::compute;       // снаружи доступно как crate::compute, а не crate::internal::compute
```

**Прелюдия** (`std::prelude`) — набор имён (`Option`, `Result`, `Vec`, `String`, `Box`, …),
которые Rust импортирует в каждый модуль **автоматически**; поэтому их не надо писать через
`use`.

## 6. Сравнение с C++: чего в Rust нет

| Задача | C++ | Rust |
|---|---|---|
| разбить объявление/определение | заголовок `.h` + `.cpp` | **не нужно**: одно определение, `pub` открывает API |
| защита от двойного включения | include guards / `#pragma once` | **не нужно**: модули не «включаются» текстом |
| пространство имён | `namespace` | `mod` (плюс управление видимостью) |
| порядок объявлений | важен, нужны forward-declaration | **не важен** внутри крейта |
| правило одного определения (ODR) | ручная дисциплина, риск нарушить | гарантируется системой модулей |
| единица сборки | translation unit (файл) | крейт (весь граф модулей) |
| сборка целей/зависимостей | CMake + пакетные менеджеры | `cargo` + `Cargo.toml` |

Rust заменяет всю связку «препроцессор + заголовки + линкер-видимость + внешний сборщик» единой
языковой моделью модулей и cargo. Целого класса проблем (забытый guard, рассинхрон `.h`/`.cpp`,
нарушение ODR) просто не существует.

## 7. Внешние крейты и зависимости

Сторонние библиотеки подключаются записью в `Cargo.toml`:

```toml
[dependencies]
rand = "0.8"                     # семантическая версия с crates.io
serde = { version = "1", features = ["derive"] }
```

`cargo` сам скачает крейт и его зависимости с [crates.io](https://crates.io) и соберёт. В коде
он доступен по имени: `use rand::Rng;`. Версии подчиняются **semver** (`"0.8"` ≈ «совместимо с
0.8.x»), а точные версии фиксируются в `Cargo.lock`. Никаких ручных путей к заголовкам,
флагов линкера и системных пакетов, как в C++.

**Workspace** — несколько связанных пакетов под одним корневым `Cargo.toml` с общей папкой
`target/` и единым `Cargo.lock` (ровно так устроен этот курс: сотни крейтов-упражнений в одном
workspace, `cargo test -p имя`).
