# M19 - Итераторы

> Часть VI "Коллекции, замыкания, итераторы". Предыдущий модуль: [M18 Замыкания](../18-closures/README.md).

## Цель модуля

Итератор - это **объект с состоянием, который по запросу отдаёт следующий элемент**.
Весь богатый API (`map`, `filter`, `sum`, ...) вырастает из одного метода `next`.
Разобрав его, вы поймёте, почему цепочка `.map().filter().sum()` не создаёт
промежуточных коллекций и компилируется в такой же цикл, как ручной, - и научитесь
писать свои итераторы, получая все адаптеры бесплатно.

После модуля вы умеете:

- [ ] объяснить трейт `Iterator` через `next` и ассоциированный тип `Item`;
- [ ] различать три формы обхода (`iter` / `iter_mut` / `into_iter`) и знать, во что
      десахаризуется `for`;
- [ ] отличать ленивый адаптер от потребителя и объяснить "адаптер без потребителя
      ничего не делает";
- [ ] строить пайплайны из `map`/`filter`/`enumerate`/`zip`/`flat_map`/`scan` и т.п.;
- [ ] сворачивать итератор потребителями (`fold`/`sum`/`find`/`any`/`collect`);
- [ ] собирать в разные типы через `collect` и `FromIterator`, включая
      collect-в-`Result` с коротким замыканием;
- [ ] реализовать `Iterator` (и `IntoIterator`) для своего типа.

## 1. Трейт `Iterator`: всё из одного `next`

Итератор - это тип, реализующий трейт с единственным обязательным методом:

```rust
pub trait Iterator {
    type Item;                              // что выдаём
    fn next(&mut self) -> Option<Self::Item>;   // Some(x) - есть элемент, None - конец
    // ... десятки методов с телом по умолчанию, все выражены через next
}
```

`next` берёт `&mut self` (итератор - объект **с состоянием**: помнит, где остановился)
и возвращает `Option`: `Some(элемент)`, пока элементы есть, и `None`, когда кончились.
Ручной обход:

```rust
let v = vec![10, 20, 30];
let mut it = v.iter();          // it: std::slice::Iter<'_, i32>
assert_eq!(it.next(), Some(&10));
assert_eq!(it.next(), Some(&20));
assert_eq!(it.next(), Some(&30));
assert_eq!(it.next(), None);
assert_eq!(it.next(), None);    // после конца - всегда None (для большинства итераторов)
```

Ключевое: итератор **ленив** и **одноразов**. Пока никто не зовёт `next`, ничего не
происходит; пройдя до `None`, итератор исчерпан. Все методы вроде `map` и `sum` -
это надстройки, которые в конце концов дёргают тот же `next`.

## 2. `IntoIterator` и три формы обхода

`for` не магия - он работает с любым типом, реализующим `IntoIterator`:

```rust
pub trait IntoIterator {
    type Item;
    type IntoIter: Iterator<Item = Self::Item>;
    fn into_iter(self) -> Self::IntoIter;
}
```

Цикл `for x in expr { body }` десахаризуется примерно в это:

```rust
let mut it = IntoIterator::into_iter(expr);
while let Some(x) = it.next() { body }
```

У коллекций три реализации `IntoIterator`, различающиеся тем, что оказывается в `Item`:

| Вызов | `Item` | Что делает с коллекцией |
|---|---|---|
| `v.iter()` | `&T` | заимствует по чтению, коллекция цела |
| `v.iter_mut()` | `&mut T` | заимствует эксклюзивно, элементы можно менять |
| `v.into_iter()` | `T` | **потребляет** коллекцию, отдаёт владение элементами |

```rust
let v = vec![1, 2, 3];
for x in &v      { /* x: &i32     */ }   // = v.iter()
for x in &mut v2 { /* x: &mut i32 */ }   // = v.iter_mut()
for x in v       { /* x: i32      */ }   // = v.into_iter(), v далее недоступна
```

Правило-мнемоника: `&collection` в `for` - это `iter()`, `&mut collection` - `iter_mut()`,
голая `collection` - `into_iter()` (и съедает её).

## 3. Адаптеры против потребителей: лень и zero-cost

Методы `Iterator` делятся на два класса:

- **Адаптеры** (`map`, `filter`, `enumerate`, `zip`, `take`, ...) возвращают **новый
  итератор** и **ничего не вычисляют**. Они лишь оборачивают исходный: `map` хранит в
  поле ваше замыкание и исходный итератор, а работу делает только когда у него позовут
  `next`. Поэтому адаптеры помечены `#[must_use]`:

```rust
let v = vec![1, 2, 3];
v.iter().map(|x| println!("{x}"));   // [!] НИЧЕГО не печатает: map ленив, никто не звал next
```

- **Потребители** (`sum`, `count`, `collect`, `for_each`, `fold`, ...) запускают
  конвейер: гоняют `next` до конца (или до короткого замыкания) и выдают результат.

Ленивость даёт **слияние (fusion)**: цепочка не создаёт промежуточных коллекций.
`v.iter().map(f).filter(p).sum()` не строит вектор после `map` и ещё один после
`filter` - каждый элемент протаскивается сквозь весь конвейер по одному. Благодаря
мономорфизации (M11) и инлайнингу компилятор разворачивает это в такой же машинный
код, как рукописный цикл, - **абстракция без накладных расходов** (zero-cost):

```rust
let s: u64 = (1..=1000).filter(|n| n % 3 == 0).map(|n| n * n).sum();
// компилируется в один цикл без единой промежуточной аллокации
```

## 4. Каталог адаптеров (ленивые)

Все возвращают итератор; работают только под потребителем.

```rust
(1..=3).map(|x| x * 2)            // 2, 4, 6           - преобразовать каждый
(1..=6).filter(|x| x % 2 == 0)    // 2, 4, 6           - оставить по предикату
["1","x","3"].iter().filter_map(|s| s.parse::<i32>().ok())  // 1, 3 - map + отсев None
"abc".chars().enumerate()         // (0,'a'),(1,'b')…  - пронумеровать с нуля
(1..).zip(["a","b"])              // (1,"a"),(2,"b")   - склеить пары, стоп по короткому
(1..=3).rev()                     // 3, 2, 1           - обратить (нужен DoubleEndedIterator)
(1..=5).skip(2)                   // 3, 4, 5           - пропустить первые n
(1..=5).take(2)                   // 1, 2              - взять первые n (обрезает бесконечные!)
(1..).take_while(|&x| x < 4)      // 1, 2, 3           - брать, пока предикат истинен
(1..=5).skip_while(|&x| x < 3)    // 3, 4, 5           - пропускать, пока истинен
vec![vec![1,2], vec![3]].into_iter().flatten()      // 1, 2, 3   - развернуть вложенность
"a b".split(' ').flat_map(|w| w.chars())            // 'a','b'   - map, затем flatten
(1..=3).chain(10..=11)            // 1,2,3,10,11       - соединить два итератора
v.iter().copied()                 // &T -> T для Copy   - разыменовать (или .cloned())
(1..=5).scan(0, |acc, x| { *acc += x; Some(*acc) })  // 1,3,6,10,15 - fold с выдачей шагов
```

Бесконечный итератор (`1..`, `std::iter::repeat`) безопасен, пока его обрезает
`take`/`take_while`/`zip` до потребления.

## 5. Каталог потребителей (запускают конвейер)

```rust
(1..=100).sum::<u64>()                  // 5050          - сумма
(1..=5).product::<u64>()                // 120           - произведение
v.iter().count()                        // длина         - досчитать до конца
(1..=5).max()                           // Some(5)
words.iter().max_by_key(|w| w.len())    // самое длинное слово
(1..=9).find(|&x| x * x > 30)           // Some(6)       - первый по предикату
(1..=9).position(|x| x == 7)            // Some(6)       - индекс первого совпадения
(1..=5).any(|x| x > 4)                  // true          - есть хоть один (короткое замыкание)
(1..=5).all(|x| x > 0)                  // true          - все подходят
(1..=5).fold(0, |acc, x| acc + x)       // 15            - общая свёртка с аккумулятором
v.iter().for_each(|x| println!("{x}"))  // побочные эффекты вместо цикла
(1..=5).nth(2)                          // Some(3)       - n-й (потребляет первые n)
```

`fold` - мать всех потребителей: `sum`, `count`, `max` выразимы через него. `any`/`all`/
`find`/`position` **коротко замыкаются** - останавливаются, не дойдя до конца.

## 6. `collect` и `FromIterator`

`collect` собирает итератор в коллекцию. Целевой тип реализует `FromIterator`, поэтому
компилятору надо его подсказать - через аннотацию переменной или турбофиш `::<>`:

```rust
let v: Vec<i32>       = (1..=3).collect();
let s: String         = vec!['a','b','c'].into_iter().collect();
let m: HashMap<_, _>  = vec![(1,"a"), (2,"b")].into_iter().collect();
let doubled = (1..=3).map(|x| x * 2).collect::<Vec<_>>();   // турбофиш вместо аннотации
```

Особый приём - **collect в `Result`/`Option`**: итератор из `Result<T, E>` собирается в
`Result<Vec<T>, E>`, останавливаясь на первом `Err`:

```rust
let ok:  Result<Vec<i32>, _> = ["1","2","3"].iter().map(|s| s.parse::<i32>()).collect();
// Ok([1, 2, 3])
let bad: Result<Vec<i32>, _> = ["1","x","3"].iter().map(|s| s.parse::<i32>()).collect();
// Err(ParseIntError) - на "x" всё оборвалось, "3" даже не парсили
```

Это точка, где связываются M16 (ошибки) и M19: пайплайн разбора превращает поток
`Result` в один `Result`, а `?` пробрасывает ошибку выше.

## 7. Свой итератор: `impl Iterator`

Реализуете `next` - получаете **все** адаптеры и потребители даром (они в трейте с
телом по умолчанию). Итератор - это тип, хранящий состояние обхода:

```rust
struct Countdown { n: u32 }

impl Iterator for Countdown {
    type Item = u32;
    fn next(&mut self) -> Option<u32> {
        if self.n == 0 { return None; }
        self.n -= 1;
        Some(self.n + 1)          // 3, 2, 1, затем None
    }
}

let c = Countdown { n: 3 };
assert_eq!(c.map(|x| x * 10).collect::<Vec<_>>(), vec![30, 20, 10]);  // адаптеры бесплатно
```

Чтобы ваш тип работал в `for` напрямую, реализуйте `IntoIterator` (обычно делегируя
своему итератору). Полезные надтрейты:

- `DoubleEndedIterator` (`next_back`) - обход с конца, включает `rev`;
- `ExactSizeIterator` (`len`) - точная длина заранее;
- `FusedIterator` - гарантия "после `None` всегда `None`".

Итератор может быть и бесконечным: `next`, который никогда не вернёт `None` (например,
Фибоначчи). Такой обязателен к обрезке `take`/`take_while` со стороны потребителя.

## 8. Типовые грабли

```rust
// 1. Ленивый адаптер без потребителя - мёртвый код
(1..=3).map(|x| do_side_effect(x));   // [!] предупреждение must_use: ничего не выполнится
(1..=3).for_each(do_side_effect);     // так - выполнится

// 2. Итератор одноразов: пройден - исчерпан
let it = v.iter();
let a: Vec<_> = it.clone().collect();  // клонируем, если нужно дважды
let b: Vec<_> = it.collect();

// 3. into_iter потребляет - после него коллекции нет
let sum: i32 = v.into_iter().sum();
// println!("{v:?}");   // [!] E0382: v перемещена в итератор

// 4. Индекс без ручного счётчика - через enumerate, а не range по длине
for (i, x) in v.iter().enumerate() { /* идиоматично */ }
```
