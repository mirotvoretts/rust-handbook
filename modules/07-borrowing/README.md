# M07 — Заимствование

> Часть II «Владение». Предыдущий модуль: [M06 Владение и move-семантика](../06-ownership/README.md).
> Дальше: [M08 Времена жизни I](../08-lifetimes-1/README.md).

## Цель модуля

Разобраться с **заимствованием** — временным доступом к значению без передачи владения — и с
правилами, которые делают его безопасным. В M03 мы уже брали `&`/`&mut`, но поверхностно.
Здесь — центральное правило Rust **«shared XOR mutable»** (общий доступ ИЛИ изменяемый, но не
одновременно), почему оно ловит целый класс багов на компиляции, и как заём взаимодействует со
срезами и структурами.

После модуля вы умеете:

- [ ] формулировать два правила заимствования и объяснять, что каждое запрещает;
- [ ] понимать «неленивые» области жизни заёма (NLL) — заём живёт до последнего использования;
- [ ] объяснять «замораживание» (freezing): пока жив `&`, владелец не может менять значение;
- [ ] возвращать заимствованные срезы (`&[T]`, `&str`) и `Option<&T>` из функций;
- [ ] брать несколько **непересекающихся** `&mut` в один срез через `split_at_mut`.

## 1. Заём против владения

**Владение** (M06) — значение принадлежит одной переменной, которая его в конце уничтожит.
**Заимствование** — взять на время **ссылку** на чужое значение, не становясь владельцем:

```rust
let s = String::from("привет");
let r = &s;            // заём: r ссылается на s, владелец по-прежнему s
println!("{r}");       // читаем через заём
// в конце s уничтожается (r владельцем не был)
```

Заём бывает двух видов:

- **`&T`** — общий (shared / immutable) заём: только чтение, таких заёмов может быть **много**;
- **`&mut T`** — исключительный (unique / mutable) заём: чтение и запись, но он **единственный**.

---

## 2. Два правила заимствования

> **В любой момент времени для значения действует ЛИБО**
> **(а) любое число общих ссылок `&T`, ЛИБО**
> **(б) ровно одна изменяемая ссылка `&mut T` — но не то и другое сразу.**
>
> **Плюс: ссылка не должна пережить значение, на которое указывает (никаких висячих ссылок).**

Первое правило — это **shared XOR mutable** (общий доступ, «исключающее ИЛИ», изменяемый).
Компилятор отвергает код, нарушающий его:

```rust
let mut v = vec![1, 2, 3];
let a = &v;             // общий заём
let b = &mut v;         // ❌ error[E0502]: нельзя &mut, пока жив &
println!("{a}");
```

```rust
let mut x = 5;
let r1 = &mut x;
let r2 = &mut x;        // ❌ error[E0499]: второй &mut одновременно нельзя
println!("{r1} {r2}");
```

Много читателей — можно; читатель и писатель одновременно — нельзя; два писателя — нельзя.

---

## 3. Зачем это правило: aliasing + mutation

Источник огромного класса багов — **одновременно** иметь два пути к данным (aliasing) и **менять**
через один из них. Классический пример — инвалидация итератора:

```rust
// Псевдокод в духе C++:
// for (auto& x : v)        // итератор держит указатель в буфер v
//     if (x == 3) v.push_back(0);  // push_back может переаллоцировать буфер →
//                                   // итератор висячий → UB
```

В Rust это **не скомпилируется**: цикл держит общий заём `v`, а `push` требует `&mut v` —
нарушение shared-XOR-mutable. То, что в C++ ловится (если повезёт) санитайзером в рантайме, в
Rust — **ошибка компиляции**. Тот же принцип исключает гонки данных в многопоточности (M22):
гонка — это ровно aliasing + mutation без синхронизации.

> [!note] Это ещё и оптимизация
> Гарантия «`&mut T` не имеет алиасов» позволяет компилятору агрессивно оптимизировать (как
> `restrict` в C, но по умолчанию и повсеместно): он знает, что запись через `&mut` никто
> больше не видит и не меняет.

## 4. Область жизни заёма (NLL)

Заём живёт **не до конца блока**, а до своего **последнего использования** — это «non-lexical
lifetimes» (NLL). Поэтому такой код корректен:

```rust
let mut v = vec![1, 2, 3];
let a = &v;                 // общий заём начинается
let n = a.len();            // ...последнее использование a — здесь заём закончился
v.push(n as i32);           // ✅ теперь можно &mut: конфликтующего заёма уже нет
```

Практический вывод: не обязательно вводить лишние области `{ }` вокруг заёмов — достаточно, что
конфликтующие использования **не перекрываются по времени**. Сначала прочитали через `&`, потом
(когда заём больше не нужен) поменяли через `&mut`.

---

## 5. Замораживание (freezing)

Пока на значение есть общий заём `&`, **сам владелец не может его менять** — значение как бы
«заморожено» на время заёма:

```rust
let mut x = 5;
let r = &x;             // заморозили x
x += 1;                 // ❌ нельзя менять x, пока жив общий заём r
println!("{r}");
```

Это прямое следствие правила: изменение владельцем — это по сути `&mut`, а он не может
сосуществовать с `&`. Как только `r` перестаёт использоваться (NLL), заморозка снимается.

---

## 6. Заём полей структуры (split borrows)

Компилятор рассуждает о заёмах **на уровне отдельных полей**, а не всей структуры: разные поля
можно заимствовать независимо, в том числе одно `&`, другое `&mut`:

```rust
struct P { x: i32, y: i32 }
let mut p = P { x: 1, y: 2 };
let rx = &p.x;          // заём поля x
let ry = &mut p.y;      // ✅ ok: другое поле, заёмы не пересекаются
*ry += *rx;
```

Это же не работает «сквозь» метод, возвращающий заём всего `self` — тогда занятой считается вся
структура. Тонкости всплывут при написании итераторов (M19).

## 7. Срезы как заём

Срез `&[T]`/`&mut [T]` — это заём непрерывного участка чужого буфера. Значит, на него
распространяются те же правила: пока жив срез в `Vec`, сам `Vec` менять нельзя (изменение может
переаллоцировать буфер и сделать срез висячим):

```rust
let mut v = vec![1, 2, 3];
let s = &v[..];         // срез заимствует буфер v
v.push(4);              // ❌ нельзя: жив общий заём s
println!("{s:?}");
```

Чтобы получить **два изменяемых** непересекающихся куска одного среза (что запрещено наивно —
`(&mut xs[..k], &mut xs[k..])` компилятор не примет напрямую), есть безопасный API
`split_at_mut`, гарантирующий непересечение:

```rust
let mut a = [1, 2, 3, 4];
let (left, right) = a.split_at_mut(2);  // left = &mut [1,2], right = &mut [3,4]
left[0] = 10;
right[1] = 40;                          // оба &mut существуют одновременно — законно,
                                        // потому что указывают в РАЗНЫЕ части
```

`split_at_mut` внутри использует `unsafe` (M26), но предоставляет безопасный интерфейс: он
**доказывает** непересечение делением по индексу.

## 8. Тизер к M08

Мы возвращали из функций заимствованные срезы (`fn tail(xs: &[i32]) -> &[i32]`) — и это
работало «само собой». На самом деле компилятор здесь выводит **время жизни**: связь «результат
живёт не дольше входа». Когда входов несколько или ссылки лежат в структурах, вывод перестаёт
справляться, и время жизни приходится **называть явно** (`'a`). Следующий модуль — **времена
жизни**: аннотации `'a`, правила элизии и хранение ссылок в структурах.
