# M20 - Умные указатели

> Часть VII "Умные указатели". Предыдущий модуль: [M19 Итераторы](../19-iterators/README.md).

## Цель модуля

Умный указатель - это **тип, который владеет данными и добавляет к обычной ссылке
поведение**: размещение на куче (`Box`), подсчёт ссылок (`Rc`/`Arc`), запуск кода при
уничтожении (`Drop`). За счёт трейтов `Deref` и `Drop` такой тип выглядит и ведёт себя
как ссылка, оставаясь обычным значением с понятными правилами владения из M06-M07.

После модуля вы умеете:

- [ ] объяснить, что делает `Box<T>` и когда он необходим (рекурсивные типы, большие
      значения, trait objects);
- [ ] строить рекурсивные типы данных, разрывая бесконечный размер через `Box`;
- [ ] объяснить `Deref`/`DerefMut` и deref coercion (`&Box<T>` -> `&T`, `&String` -> `&str`);
- [ ] реализовать свой умный указатель с `Deref` и увидеть, как работает `Box` внутри;
- [ ] писать `Drop` для RAII-очистки и понимать порядок уничтожения (LIFO);
- [ ] разделять владение через `Rc<T>`, читать `strong_count`, дёшево клонировать
      `Rc::clone`;
- [ ] отличать `Rc` от `Arc` и знать цену атомарного счётчика.

## 1. Зачем нужны умные указатели

Обычная ссылка `&T` только заимствует - она ничем не владеет и ничего не делает при
выходе из области видимости. Умный указатель - это структура, которая **владеет**
данными и реализует два трейта:

- `Deref` - чтобы к нему можно было обращаться как к `&T` (разыменование, вызов
  методов `T`);
- `Drop` - чтобы при уничтожении освободить ресурс (память, файл, замок).

`String` и `Vec<T>` из M17 - уже умные указатели: владеют буфером на куче, дают доступ
к нему как к срезу, освобождают его в `Drop`. В этом модуле - "голые" указатели из
стандартной библиотеки: `Box`, `Rc`, `Arc`.

## 2. `Box<T>`: единоличное владение на куче

`Box<T>` кладёт значение типа `T` в кучу, а на стеке держит только указатель. Владение
единоличное: `Box` ведёт себя как сам `T` в смысле move/drop.

```rust
let b = Box::new(5i32);   // 5 лежит на куче, b на стеке - указатель
println!("{}", *b);        // *b = 5: разыменование ведёт к значению
// при выходе b из области видимости куча освобождается автоматически
```

Когда `Box` действительно нужен (а не просто лишняя аллокация):

1. **Рекурсивные типы** - тип, содержащий сам себя. Без косвенности его размер
   бесконечен (см. раздел 3).
2. **Большое значение, которое часто перемещают** - move `Box` копирует указатель
   (8 байт), а не весь объект.
3. **Trait objects** (M14) - `Box<dyn Trait>` хранит значение неизвестного размера
   за указателем.
4. **Владеющая передача значения неизвестного размера** через границу API.

Аллокация идёт через глобальный аллокатор (`GlobalAlloc`); `Box::new` - это запрос
блока памяти и запись туда значения, drop - возврат блока.

## 3. Рекурсивные типы

Классический пример - список "cons" (голова + хвост):

```rust
enum List {
    Cons(i32, List),   // [!] E0072: recursive type has infinite size
    Nil,
}
```

Размер `List` = размер `i32` + размер `List` + ... - бесконечность. Компилятор не может
разложить его на стеке. Решение - косвенность фиксированного размера: `Box` (указатель
всегда 8 байт, независимо от того, на что указывает):

```rust
enum List {
    Cons(i32, Box<List>),   // теперь размер = i32 + указатель: конечный
    Nil,
}

use List::{Cons, Nil};
let list = Cons(1, Box::new(Cons(2, Box::new(Cons(3, Box::new(Nil))))));
```

То же с бинарным деревом: `Node { value, left: Option<Box<Node>>, right: Option<Box<Node>> }`.
`Option<Box<T>>` - идиома "может быть узел, может быть его нет" без лишнего уровня.

## 4. `Deref` и `DerefMut`: указатель ведёт себя как ссылка

`*b` для умного указателя - это сахар над трейтом `Deref`:

```rust
pub trait Deref {
    type Target: ?Sized;
    fn deref(&self) -> &Self::Target;   // *b десахаризуется в *(b.deref())
}
```

Реализовав `Deref`, вы получаете **deref coercion** - компилятор автоматически
вставляет `.deref()`, приводя `&SmartPointer<T>` к `&T` там, где ждут `&T`:

```rust
fn hello(name: &str) { println!("hi {name}"); }

let b = Box::new(String::from("Rust"));
hello(&b);        // &Box<String> -> &String -> &str: две коерции подряд, всё на этапе компиляции
```

Поэтому методы `T` доступны прямо на `Box<T>`: `b.len()` на `Box<String>` - это
`(*b).len()`, куда компилятор дошёл через `deref`. `DerefMut` - то же для `&mut`.
Коерция срабатывает при передаче аргументов, вызове методов и в некоторых
присваиваниях; она бесплатна в рантайме - это переписывание на этапе компиляции.

Известные коерции стандартной библиотеки: `&String -> &str`, `&Vec<T> -> &[T]`,
`&Box<T> -> &T`, `&Rc<T> -> &T`.

## 5. `Drop`: код при уничтожении и RAII

`Drop` задаёт деструктор - код, который выполнится, когда значение уходит из области
видимости. Это фундамент RAII (M16): ресурс освобождается автоматически и детерминированно.

```rust
struct Guard { name: String }

impl Drop for Guard {
    fn drop(&mut self) {
        println!("освобождаю {}", self.name);
    }
}

{
    let _a = Guard { name: "a".into() };
    let _b = Guard { name: "b".into() };
}   // печатает "b", затем "a": порядок уничтожения ОБРАТЕН порядку создания (LIFO)
```

Правила:

- Порядок drop локальных переменных - **обратный** объявлению; поля структуры
  дропаются в порядке объявления.
- Нельзя вызвать `x.drop()` вручную (E0040) - иначе значение дропнулось бы дважды.
  Чтобы уничтожить раньше срока, есть `std::mem::drop(x)` - забирает значение по
  владению и роняет его:

```rust
let g = Guard { name: "g".into() };
drop(g);            // деструктор сейчас
// g больше недоступна: перемещена в drop
```

- `Drop` и `Copy` несовместимы: `Copy`-тип не может иметь деструктор.

## 6. `Rc<T>`: разделяемое владение

`Box` - один владелец. Иногда у данных должно быть **несколько** владельцев, и данные
живут, пока жив хоть один (граф, дерево с общими поддеревьями, разделяемая
конфигурация). `Rc<T>` (reference counted) хранит рядом со значением счётчик сильных
ссылок:

```rust
use std::rc::Rc;

let a = Rc::new(String::from("shared"));
let b = Rc::clone(&a);            // НЕ копирует строку - только +1 к счётчику
let c = Rc::clone(&a);
assert_eq!(Rc::strong_count(&a), 3);   // три владельца одних данных
// значение освободится, когда счётчик дойдёт до 0 (последний Rc дропнут)
```

- `Rc::clone(&a)` дёшев: инкремент счётчика, а не глубокое копирование. По конвенции
  пишут `Rc::clone(&a)`, а не `a.clone()`, чтобы клон-указателя было видно в коде.
- `Rc<T>` даёт только **разделяемый доступ** (`&T`): изменять данные через него нельзя,
  ведь владельцев много и это нарушило бы shared-XOR-mutable (M07). Мутация под общим
  владением - отдельная тема (interior mutability).
- `Rc` не потокобезопасен (счётчик не атомарный), поэтому не `Send`. Внутри одного
  потока - самый дешёвый способ разделить владение.

Осторожно с **циклами**: если два `Rc` ссылаются друг на друга, счётчик никогда не
дойдёт до нуля - память утечёт. Строя циклические структуры, разрывайте цикл слабой
ссылкой, не удерживающей значение.

## 7. `Arc<T>`: атомарный счётчик для потоков

`Arc<T>` (atomically reference counted) - тот же `Rc`, но счётчик меняется атомарными
операциями, поэтому `Arc` можно делить между потоками (он `Send + Sync`, если `T`
таков):

```rust
use std::sync::Arc;
let data = Arc::new(vec![1, 2, 3]);
let d2 = Arc::clone(&data);   // безопасно уедет в другой поток
```

Цена атомарности - каждый clone/drop дороже, чем у `Rc`. Правило: `Rc` внутри одного
потока, `Arc` - когда данные пересекают границу потока. API идентичен `Rc`. Детали
многопоточности - в части VIII.

## 8. Типовые грабли

```rust
// 1. Рекурсивный тип без косвенности не компилируется
enum Tree { Node(i32, Tree, Tree) }   // [!] E0072: бесконечный размер -> оберни в Box

// 2. Ручной вызов деструктора запрещён
let g = Guard { .. };
g.drop();          // [!] E0040: explicit destructor call -> используй drop(g)

// 3. Rc не даёт &mut
let r = Rc::new(vec![1, 2]);
r.push(3);         // [!] нельзя: Rc отдаёт только &T, не &mut T

// 4. Клонирование Rc - это указатель, а не данные
let a = Rc::new(big_data());
let b = a.clone();  // дёшево (счётчик), но пиши Rc::clone(&a) для ясности

// 5. Цикл Rc <-> Rc = утечка
// счётчик обоюдно не обнуляется; циклы разрывают слабой ссылкой
```
