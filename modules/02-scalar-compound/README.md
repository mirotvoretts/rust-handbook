# M02 — Скалярные и составные типы

> Часть I «Основы языка». Предыдущий модуль: [M01 Значения и поток управления](../01-basics/README.md).
> Дальше: [M03 Функции и ссылки](../03-functions-refs/README.md).

## Цель модуля

Разобрать «атомы» системы типов Rust: **целые** разных разрядностей и что происходит при
**переполнении**, **числа с плавающей точкой**, `bool`, `char` (не байт, а Unicode-скаляр), и
**составные** типы — **кортежи**, **массивы**, **срезы**. Rust здесь заметно строже C/C++:
никаких неявных приведений, переполнение знаковых — не UB, а определённое поведение, а `char`
— это полноценный Unicode scalar value шириной 4 байта.

После модуля вы умеете:

- [ ] выбирать целочисленный тип (`i32`/`u64`/`usize`/…) и читать литералы с суффиксами;
- [ ] объяснить поведение переполнения (паника в debug, обёртка в release) и применять
      `wrapping_`/`checked_`/`saturating_`/`overflowing_`;
- [ ] приводить типы через `as` и понимать, что теряется;
- [ ] работать с `f64` и знать про `NaN`, отсутствие `==`/`Ord`, сравнение через ε;
- [ ] отличать `char` (4 байта, Unicode) от байта, а `&str` (UTF-8) — от массива символов;
- [ ] деструктурировать кортежи, индексировать массивы, брать срезы и диапазоны.

## 1. Целочисленные типы

| Разрядность | знаковый | беззнаковый |
|---|---|---|
| 8 | `i8` | `u8` |
| 16 | `i16` | `u16` |
| 32 | `i32` (по умолчанию) | `u32` |
| 64 | `i64` | `u64` |
| 128 | `i128` | `u128` |
| размер указателя | `isize` | `usize` |

- **`i32` — тип по умолчанию** для целочисленного литерала без суффикса и без контекста.
- **`usize`/`isize`** имеют разрядность указателя платформы (64 бита на современных ПК) и
  используются для **индексов и размеров** (`Vec::len` возвращает `usize`, индексация требует
  `usize`). Это ближе всего к C `size_t`/`ptrdiff_t`.
- Литералы: `98_222`, `0xff`, `0o77`, `0b1010`, `b'A'` (байтовый литерал = `u8`). Суффикс
  задаёт тип: `42u8`, `1_000i64`, `2.0f32`.

В отличие от C/C++, где разрядность `int`/`long` зависит от платформы и компилятора, в Rust
`i32` — это **всегда** ровно 32 бита. Никакого «implementation-defined» размера.

## 2. Переполнение — определённое поведение, а не UB

Это одно из принципиальных отличий от C и C++. Там **знаковое** переполнение — undefined
behavior (компилятор вправе делать что угодно). В Rust переполнение определено:

- **в debug-сборке** — программа **паникует** (`attempt to add with overflow`);
- **в release-сборке** (`--release`) — значение **оборачивается** по модулю 2ⁿ (two's complement).

Полагаться на «тихую обёртку» по умолчанию нельзя — правильнее выбрать явную операцию под
намерение:

```rust
let a: u8 = 250;
a.wrapping_add(10)      // 4     — оборачивание по модулю (всегда, в любой сборке)
a.checked_add(10)       // None  — Option: None при переполнении, иначе Some(sum)
a.saturating_add(10)    // 255   — «прилипает» к границе типа
a.overflowing_add(10)   // (4, true) — (обёрнутый результат, был ли перенос)
```

| Метод | Возврат | Когда применять |
|---|---|---|
| `wrapping_*` | обёрнутое значение | хэши, счётчики по модулю, криптопримитивы |
| `checked_*` | `Option<T>` | когда переполнение — ошибка, которую надо обработать |
| `saturating_*` | значение у границы | «зажать» в диапазон (громкость, прогресс) |
| `overflowing_*` | `(T, bool)` | нужен и результат, и флаг переноса |

### Приведение `as`

```rust
let n: i32 = 300;
n as u8            // 44   — берёт младшие 8 бит (300 mod 256), БЕЗ паники
let f = 3.9_f64;
f as i32           // 3    — усечение к нулю (не округление)
let big = 300_i32;
big as u8          // 44
-1_i32 as u8       // 255  — битовое представление
```

`as` — **всегда молчит** (не паникует, не даёт `Option`) и может терять данные. Это осознанно
низкоуровневый инструмент; для «безопасного сужения с проверкой» есть `TryFrom`/`try_into`
(модуль M13). Неявных числовых приведений, как в C (`int` → `double`, `char` → `int`), в Rust
**нет вообще** — всякое смешивание типов явно.

## 3. Числа с плавающей точкой

Типы `f32` и `f64` (по умолчанию — **`f64`**), стандарт IEEE-754.

```rust
let x = 0.1_f64 + 0.2;      // 0.30000000000000004, а не 0.3
```

Ключевые следствия, отличающие float от целых:

- **Нельзя сравнивать на равенство** напрямую: из-за ошибок округления `0.1 + 0.2 == 0.3`
  ложно. Сравнивайте через ε: `(a - b).abs() < 1e-9`.
- **`NaN` не равен ничему**, включая себя: `f64::NAN == f64::NAN` — `false`. Поэтому `f64`
  реализует лишь частичный порядок `PartialOrd`, но **не** `Ord`, и не `Eq`. Из-за этого,
  например, `Vec<f64>` нельзя отсортировать через `.sort()` (нужен `.sort_by`).
- Специальные значения: `f64::INFINITY`, `f64::NAN`, `-0.0`. Методы: `.sqrt()`, `.abs()`,
  `.floor()`, `.powi(2)`, `.is_nan()`.

Это ровно та же IEEE-754-семантика, что в C++/Java, но Rust **встраивает** её последствия в
систему типов (нет `Ord` → компилятор не даст случайно отсортировать/положить в `BTreeSet`).

## 4. `bool` и `char`

`bool` — `true`/`false`, размер 1 байт. Никаких неявных «число как условие» (`if 1` не
компилируется) — в отличие от C/C++.

`char` — **Unicode scalar value**, занимает **4 байта** и хранит один кодовый пункт
(`U+0000..=U+D7FF` и `U+E000..=U+10FFFF`):

```rust
let c: char = 'z';
let emoji: char = '😻';     // один char, хотя в UTF-8 это 4 байта
let newline = '\n';
```

Это фундаментально отличается от C, где `char` — это байт (`u8`). В Rust «байт» и «символ» —
**разные типы**: байтовый литерал `b'A'` имеет тип `u8`, символьный `'A'` — тип `char`. Полезные
методы: `c.is_alphabetic()`, `c.is_numeric()`, `c.is_whitespace()`, `c.to_ascii_uppercase()`,
`c.to_digit(10) -> Option<u32>`.

> [!note] Почему символ — 4 байта, а строка — UTF-8
> `char` фиксированной ширины удобно передавать и сравнивать. Но хранить текст массивом
> `char` расточительно (4 байта на символ), поэтому строки `String`/`&str` хранятся в **UTF-8**
> (1–4 байта на символ). Отсюда — §8: у строки длина в **байтах** и число **символов** это
> разные величины.

## 5. Кортежи

Кортеж — **анонимное произведение** фиксированного набора значений (возможно, разных типов):

```rust
let t: (i32, f64, char) = (1, 2.5, 'x');
let first = t.0;                 // доступ по индексу-полю
let (a, b, c) = t;              // деструктуризация
```

Кортежи — идиоматичный способ **вернуть из функции несколько значений** (в C для этого нужен
`struct` или выходные параметры-указатели):

```rust
fn divmod(a: i32, b: i32) -> (i32, i32) { (a / b, a % b) }
let (q, r) = divmod(17, 5);      // q = 3, r = 2
```

Пустой кортеж `()` — тип и значение **unit**, аналог `void`: его возвращают выражения без
осмысленного результата. Кортеж из одного элемента пишется `(x,)` (с запятой).

## 6. Массивы `[T; N]`

Массив — **фиксированное** число элементов **одного типа**, длина `N` — **часть типа** и
известна на компиляции. Лежит на стеке (инлайн), без аллокации кучи:

```rust
let a: [i32; 5] = [1, 2, 3, 4, 5];
let zeros = [0; 100];            // сто нулей: [значение; количество]
let x = a[0];                    // индексация
let n = a.len();                 // 5
```

Выход за границу — **паника** в рантайме (`index out of bounds`), а **не** чтение чужой памяти,
как в C. Проверку границ Rust вставляет автоматически (и часто оптимизирует, когда может
доказать безопасность). Массив с длиной в типе (`[i32; 5]` и `[i32; 6]` — разные типы) удобен,
когда размер известен заранее; для динамического размера есть `Vec<T>` (M17).

## 7. Срезы `&[T]` и `&str`

**Срез** — «вид» на непрерывный участок последовательности: пара «указатель + длина» (**жирный
указатель**, fat pointer), не владеющая данными. `&[T]` — срез массива/вектора, `&str` — срез
строки (гарантированно валидный UTF-8):

```rust
let a = [10, 20, 30, 40, 50];
let mid: &[i32] = &a[1..4];       // [20, 30, 40] — диапазон, полуоткрытый
let all: &[i32] = &a;            // весь массив как срез
mid.len();                       // 3
mid.first();                     // Option<&i32>

let s: &str = "привет";
s.len();                          // 12 — длина в БАЙТАХ (UTF-8), не в символах!
s.chars().count();               // 6  — число символов
&s[0..2];                         // "п" — срез по БАЙТОВЫМ границам (паника, если разрежет символ)
```

Срез — то, как функции принимают «любую последовательность, не забирая владения»: `fn
sum(xs: &[i32])` работает и для массива, и для `Vec`. Это Rust-аналог пары «указатель + размер»
из C (`func(int* p, size_t n)`), но безопасный: длина едет вместе с указателем, выход за границу
паникует, а не портит память.

> [!warning] Байты против символов
> `"π".len()` == 2, а `"π".chars().count()` == 1. Индексация строки байтовым диапазоном,
> разрезающим многобайтовый символ (`&"π"[0..1]`), **паникует**. Строки в Rust нельзя
> индексировать по символу через `s[i]` — это следствие UTF-8 (произвольный доступ к i-му
> символу не O(1)). Подробно строки — в M17.
